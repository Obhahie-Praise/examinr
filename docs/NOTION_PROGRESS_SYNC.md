# Examinr → Notion Progress Sync

This integration sends meaningful Examinr development events to the **Progress Updates** data source in the Personal Operating System.

## Endpoint

`POST /api/integrations/notion/progress`

The endpoint is server-to-server. It is protected by a bearer secret and must never be called directly from browser code.

## Required Worker configuration

Set these values in the API Worker:

| Variable | Type | Value |
|---|---|---|
| `NOTION_API_KEY` | Secret | Internal Notion integration token |
| `EXAMINR_NOTION_SYNC_SECRET` | Secret | A new, high-entropy secret shared only by trusted Examinr server code and this Worker |
| `NOTION_PROGRESS_DATA_SOURCE_ID` | Variable | `d4e52c31-8e19-41cb-939a-f69dcccc2f95` |
| `NOTION_EXAMINR_PROJECT_PAGE_ID` | Variable | `414e9fd7-05ba-819c-8ec0-f42baeacded0` |

Do not commit secret values, put them in `.dev.vars.example`, or expose them to the web application.

## Notion integration setup

1. Create an internal integration in Notion.
2. Give it permission to insert content in the workspace.
3. Share the **Progress Updates** database with that integration using the database's Connections menu.
4. Confirm the integration can access the Examinr project relation target. The project page is inside the Projects database.
5. Copy the integration token directly into the API Worker secret configuration. Never paste it into ChatGPT or source code.

The data source ID and Examinr project page ID above are identifiers, not secrets.

## Cloudflare Worker secrets

From the repository root, configure the API Worker secrets using Wrangler:

```powershell
pnpm --filter api exec wrangler secret put NOTION_API_KEY
pnpm --filter api exec wrangler secret put EXAMINR_NOTION_SYNC_SECRET
```

Configure the two non-secret IDs as Worker vars in the Cloudflare dashboard or the appropriate Wrangler environment configuration. Do not add production secrets to `wrangler.jsonc`.

For local development, place the same values in `apps/api/.dev.vars` (never commit this file):

```dotenv
NOTION_API_KEY=secret_xxx
EXAMINR_NOTION_SYNC_SECRET=replace-with-a-long-random-secret
NOTION_PROGRESS_DATA_SOURCE_ID=d4e52c31-8e19-41cb-939a-f69dcccc2f95
NOTION_EXAMINR_PROJECT_PAGE_ID=414e9fd7-05ba-819c-8ec0-f42baeacded0
```

## Event contract

```json
{
  "eventId": "stable-unique-event-id",
  "title": "Implemented topic-level practice history",
  "updateType": "Build log",
  "date": "2026-11-10",
  "summary": "Students can now review their recent topic practice.",
  "workCompleted": "Persisted completed attempts and connected the review screen.",
  "tests": "API integration tests passed; web type-check passed.",
  "blockers": "",
  "nextSteps": "Add topic-level performance aggregation.",
  "evidenceUrl": "https://example.com/evidence",
  "commitUrl": "https://github.com/owner/repo/commit/..."
}
```

Required fields: `eventId`, `title`, and `summary`. Optional text and URL fields may be omitted. Dates default to the Worker date. URLs must be HTTPS.

Supported `updateType` values: `Build log`, `Milestone`, `Decision`, `Bug / blocker`, `Release`, `Research`, and `Other`.

## Authentication

Send the shared secret in the HTTP Authorization header:

`Authorization: Bearer <EXAMINR_NOTION_SYNC_SECRET>`

Never send the Notion integration token from Examinr to this endpoint. The API Worker owns the Notion token and performs the Notion write server-side.

## Idempotency and retries

- Each event must use a stable `eventId` generated by Examinr.
- The API stores event state in D1 before writing to Notion.
- Repeated successful events return `200` with `status: duplicate` and do not create another row.
- Before creating a page, the API queries Notion for the same external event ID. This recovers if Notion accepted the previous write but the API timed out before storing the Notion page ID in D1.
- Concurrent requests for an event already processing return `409`.
- Failed writes can be retried using the same event ID.
- Successful writes return `201` and the Notion page ID.

## Migration and deployment

Apply the D1 migration before deploying the updated Worker:

```powershell
pnpm --filter api drizzle:migrate:local
pnpm --filter api drizzle:migrate:remote
```

Deploy only after the secrets, vars, and Notion integration sharing are configured.

## Verification checklist

- [ ] Notion integration can create a row in Progress Updates.
- [ ] Missing/invalid bearer secret returns 401.
- [ ] Invalid payload returns 400.
- [ ] First valid event creates one Examinr-linked row.
- [ ] Replaying the same event ID returns duplicate without creating another row.
- [ ] A failed Notion write can be retried with the same event ID.
- [ ] No Notion token is present in client bundles, logs, or committed files.
- [ ] A real Examinr server workflow emits an event after a meaningful milestone.

Until these checks pass, the integration must be described as implemented but not yet live/verified.
